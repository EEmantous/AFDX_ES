# V3 内部异常与运行统计

统计位于 `AFDX_top.u_stats`，共 36 个 32 位无符号统计地址槽，其中 34 项有效，2 项保留为零。地址为字节地址，四字节对齐，范围 `0x00～0x8C`。`stats_addr` 组合选择 `stats_rdata`；未对齐或越界地址返回 0，`stats_error=1`。这些端口是内部统计的调试读口，尚未实现 SNMP。

`stats_clear=1` 在时钟沿清所有计数，优先于同拍事件；清零不复位 TX/RX、序列表、消重历史或在途帧诊断状态。全局 reset 清计数。到 `0xFFFFFFFF` 后保持饱和。A/B 每种事件使用不同计数器，两路同拍异常分别加一。

## 计数的解释

丢弃总数和原因计数会重叠，例如一个 SN0 帧使本路 DROP、SEQUENCE_DROP、SEQUENCE_ERROR 各加一；不能把所有原因相加当作帧数。序列跳号表示不连续事件，可能是整帧丢失或乱序，不等于能精确还原丢失帧数量。

正常 A/B 副本在两路分别通过校验后，可能使两个 ACCEPTED 都加一，合并器 DUPLICATE 加一，而 APP_RX_FRAMES 只加一。这是冗余合并的正常行为。反压周期也不直接等于错误。

入口超长在确认时立即计数和排空，随后因空闲退出排空不会再加 TIMEOUT，避免同一非法流被重复分类。无 last 且持续发送的超长流会持续被吸收丢弃，到 last 或连续空闲阈值才恢复；缺 last 的有限半帧在连续空闲阈值后恢复。

TX_APP_TIMEOUT 仅诊断半帧，不自动删除 TX FIFO 内字节。TX 超长若形成结束帧会由已有 fanout 核心限长拒绝，但 TX 缺 last 填满 FIFO 的自动恢复仍是后续工作。

## 默认配置与接口边界

`RX_IDLE_TIMEOUT_CYCLES=12500`，80 ns 时钟下 1 ms；`TX_IDLE_TIMEOUT_CYCLES=12500` 独立配置。只有未完成 RX 输入且没有 valid 才计算入口空闲；合法完整帧等待 decoder、APP 或下游 ready 时不启动缺帧超时。TX 输入监测同样不把正常 ready=0 计为输入停止。

当前流只有 data/valid/last/ready，没有独立 start-of-frame。缺 last 后必须出现 last 或足够长的空闲边界才能确定恢复位置；连续紧接的新帧无法凭字节可靠推断帧首，会继续排空。本轮按用户安排暂不对齐题目 MAC 模板；之后如加入明确帧首/错误信号，可进一步缩短恢复时间。

使用示例：选择 `stats_addr=8'h2C` 读取 A 超长计数；`8'h5C` 读取 B 超长；`8'h30/60` 读取两路缺帧超时；`8'h88` 读取最终 APP 交付数。读口无写寄存器操作，清零只通过 stats_clear 一拍完成。
