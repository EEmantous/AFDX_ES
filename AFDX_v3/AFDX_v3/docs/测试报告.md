## 2. 新增保护/统计场景

一个真实AFDX_top，测试时钟10ns，RX/TX空闲阈值各16拍，BAG=1拍；这是功能边界自检配置，不是默认1ms的性能测量。所有APP交付逐字节检查data/last/VLID/SN，反压期间比较完整33位保持值。

|场景|自检结论|
|---|---|
|A连续6000字节无last，B7000字节末尾last，同时输入|各路超长/丢弃只计1次；持续排空无写地址回绕；A空闲退出排空不再计超时；APP无泄漏|
|A44字节、B900字节半帧后停止，无last|两路各超时丢弃一次，入口释放，后续可恢复|
|A59字节短帧，B完整60字节但头声明多1|A入口短帧拒绝；B保持正确IP校验以独立测试长度检查，parser拒绝|
|两路合法1514字节最大核心帧、不同VL同SN|正确交付两帧1471字节载荷及完整身份，合法最大边界不误丢|
|APP停止接收，A连续多帧直到实际RX输入反压，等待80拍再恢复|超过16拍超时阈值的正常反压不计缺帧，全部合法帧恢复交付，APP身份保持|
|A同路重复、B跨网迟到重复、A跳号、B SN0、A坏IP校验后再发合法|序列拒绝/错误、parser错误和合并丢副本分别计数；合法后续仍交付；共10次预期APP交付|
|统计清零后TX合法帧、B副本暂停后完整恢复、1472字节APP帧、8字节无last半帧|实际A/B帧计数、两个保留地址读零、APP/核心超长及半帧诊断按预期；缺last静止时不重复计数|
|统计地址不对齐/越界、near-wrap预置、clear与事件同拍|无效读0/error；计数到ffffffff饱和；clear优先|

饱和边界使用独立afdx_es_stats叶子DUT，将测试计数预置为fffffffe后送多个事件，不声称已实际仿真2^32个事件。首次新增TB按旧RX直通延迟过早读计数，后来等待完整帧保护、parser和载荷合并的真实流水线时长；最终全回归和XSim都通过。旧失败记录保留。本轮另将迟到副本TB的顺序端口连接改为命名连接，适应删除使能端口后的接口；最终10/10回归通过。

RX核心帧缓存当前为异步读，综合使用分布式RAM；统计含36个地址槽，两个保留事件固定为零。本轮删除独立许可、按路复位与取消逻辑后，LUT由6704降为6641、寄存器由2811降为2807。删除未接入模块不会使主顶层原本未例化的逻辑资源减少。当前功能与资源可用，后续如需降低LUT可改同步RAM输出并验证读流水线。

时序仅证明已指定内部综合约束满足，I/O delay尚未按实际MAC设置，未布局布线。8位/80ns是理论100Mbps字节节奏，不代表持续吞吐、最坏延迟或抖动已达标。完整帧前置缓存增加捕获延迟，应纳入性能测量。
